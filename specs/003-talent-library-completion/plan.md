## 2. 阶段 1：方案 A 紧凑首页与底栏修复

- 保留四个底部入口。首页第一行：舞蹈/吉他/唱歌切换、批量管理、收录；第二行：搜索和筛选。删除重复的大标题，取消左侧状态栏和常驻场景栏。
- 筛选使用底部面板：学习状态单选；舞蹈场景多选，沿用现有场景交集语义。重置先改面板草稿，应用才生效；取消不改变已有条件。按钮显示当前状态及场景数量。吉他/唱歌只展示其适用筛选。
- 三类列表全宽两列，封面标准高度约 80dp，标题最多两行；不再在封面下重复歌名。隐藏空歌手/“未识别”，真实歌手保留；分类、时长、播放、勾选可读可操作。详情保留完整标题。大字体下允许卡片增高，触控目标不少于 48dp。
- 顶部随页面滚动。底栏不透明并建立明确显示层级；卡片文字不能穿过底栏。播放条、批量操作条位于底栏之上，以实际占用高度计算内容底部留白；两种条不同时叠出，进入批量时暂停播放。
- 验收：浅/深主题、长歌名、大字体、滚动到底、播放/批量操作时底栏均可见和可点；最后一首可完整滚入可操作区域。固定真机标准字号下，完整可见曲目数比现有首页增加。

## 3. 阶段 2：三类曲库管理完整化

### 新增与查询

- 舞蹈保留文件/链接收录；吉他和唱歌保留先建文本再加音频。三类增加多文件收录入口，一次最多选择 50 个文件，各自显示处理结果、失败原因和重试；现有单文件 512MiB 上限保留。处理阶段不伪装为整批事务，已成功文件保留，重试不重复生成条目。
- 收录确认页支持逐条改歌名及统一学习状态，按当前才艺创建；无效条目不提交，失败项可单独补齐。已存在的曲目不自动覆盖，用户可选择跳过重复项。
- 查询覆盖才艺、歌名/歌手、学习状态；舞蹈保留场景筛选，增加仅示例和仅已缓存开关。默认普通列表隐藏回收站曲目。

### 编辑、批量与删除

- 三类都有单条完整编辑和批量管理。批量选择限定当前才艺，切换才艺或筛选时清空选择；“全选当前结果”明确显示首数，不含隐藏结果或回收站。
- 批量支持学习状态、加入节目单和删除；舞蹈支持标签增/删/替换，吉他支持原调/演奏调/Capo，唱歌支持原调/演唱调/音频用途。资料默认保持原值，只有明确选择的字段批量修改。不把多首歌名改成同一个名字。
- 删除默认为“移入回收站”，弹窗显示数量和曲名清单，明确原始媒体保留。成功后更新曲库、节目单和本地快照；失败保留选择，不虚报部分成功。
- “我的→回收站”支持查询、单条/批量恢复、永久删除记录；恢复不自动恢复旧节目单位置。回收站不定时自动清空。永久删除记录再次确认，仍不顺带删除原始媒体。
- 客户端清缓存仍只处理可重下载缓存。原始媒体保留现有单条显式删除能力，补齐跨才艺与谱件引用检查；本轮不提供批量删除原始素材的快捷操作。
- 数据修改整批校验后单事务提交；失败整批回滚。批量请求带 operationId，重复提交返回原结果，避免响应丢失后的重复执行。
- 验收：三类增删改查可用；批量空选、重复 ID、未知/已删除 ID、非法字段、事务中途失败、重复提交、取消删除、恢复、节目单移除均有测试；共享素材不误删。

## 4. 阶段 3：可试用、可清理的示例

- “我的→示例数据”提供导入示例、清除示例、已导入数量。使用项目自制短音乐与文本，三类各一首；吉他有调性、Capo、和弦谱，唱歌有歌词和伴奏，舞蹈有分类。
- 独立示例登记表追踪记录与素材 ID，曲目显示“示例”角标。编辑不取消示例身份；清除时提示会移除对示例的编辑。
- 重复导入不追加、不覆盖已编辑示例，缺失项可补齐。只下载示例所需文件，不借此重下全部真实音乐。提供一张自制谱图和一份两页 PDF，阶段 5 完成后供用户体验。
- 清除仅移除登记的示例记录、节目单引用和不再共享的示例文件/缓存，不能按歌名或标签匹配删除。API 失败则保持内容并提示，不能只在手机隐藏来假装成功。
- 交付时导入并保留一套示例。测试用破坏性用例在隔离库完成；用户试用示例不自动清理，也不自动发声。
- 验收：重复导入、缺项补齐、下载中断重试、修改后清除、素材共享和真实曲目保护通过；示例缓存后可断网体验。

## 5. 阶段 4：混合节目单与现场演出

- 底部“今晚歌单”显示名改为“今晚节目单”，仍只维护一份当前节目单。可加入舞蹈/吉他/唱歌，搜索、分类选择、多选加入、拖动或上下移动排序、移出和清空；同一曲目不重复加入，清空需确认。
- 新节目单用 {kind,id} 引用三类记录；既有 string[] 舞蹈歌单按原顺序迁入。删除和清除示例同步移出节目单。旧舞蹈 API 保留兼容，新增混合接口不让旧请求抹掉吉他/唱歌项。
- 演出页按节目顺序显示：舞蹈大播放按钮；吉他突出谱、调性、Capo；唱歌突出歌词和伴奏用途。支持上一项、下一项、暂停、从头和屏幕常亮。进入页面、切项、自然结束均不自动发声；切项停止上一项。
- 无节目单时按当前才艺显示已掌握曲目；舞蹈会跳、吉他会弹、唱歌会唱。显式加入节目单的曲目不被学习状态偷偷过滤掉。
- 纯文本吉他/唱歌可以作为节目，标为“看谱/歌词，无音频”，不算缓存失败。“准备离线演出”检查节目所需音频、谱件和元数据，明确已就绪/缺失；缺失音频不能在现场静默回落网络。
- 验收：三类混排、旧歌单迁移、排序持久化、删除引用处理、纯文本节目，以及混合节目单物理断网冷启动均通过；切项和播放结束不自动下一首。

## 6. 阶段 5：谱件与手机离线编辑

### 图片/PDF 与阅读

- 吉他/唱歌可附加 JPG/PNG/WebP 图片或 PDF，一首可多个，支持排序、移除、缩放、翻页、阅读位置记忆。单图上限 10MiB，PDF 上限 25MiB/100页；实际格式校验，超限、损坏或加密文件明确拒绝，不覆盖旧谱。
- PDF 使用官方 PDF.js display layer，worker、字体和 CMap 等资源随 APK 打包，不依赖 CDN；按当前页及相邻页按需渲染，避免整本驻留内存。图片/PDF 保留原件，阅读器不执行 PDF 脚本或自动打开外部链接。
- 手动滚动为默认；文本谱/歌词增加可调速自动滚动，手动触摸暂停自动滚动；不做歌词时间轴、OCR、自动和弦转换或音频自动换调。
- 全曲库下载增加谱件选项，默认同时下载谱件；原始视频继续不批量缓存。节目单就绪检查包括附加谱件。移除谱件只解绑记录，共享原件受引用保护。

### 离线操作与同步

- 手机可离线编辑三类资料、分类，软删除/恢复，创建吉他/唱歌文本曲目，以及修改节目单；立即本地生效并标记“待同步”。舞蹈新文件、音频和谱件可离线暂存，联网后由 Mac 处理；处理中不能声称已有派生音频。
- 使用 IndexedDB 保存曲库元数据、节目单和持久操作队列，原生 Filesystem 保存媒体；迁移现有 localStorage 快照时校验数量和内容，成功前保留旧数据。新增记录使用客户端 UUID，关联操作按依赖顺序同步。
- 服务端给记录和节目单增加 revision；同步请求携带 operationId 和 baseRevision。重复请求不重复执行；版本冲突保留手机草稿及服务器版本，不自动覆盖。冲突集中放“我的→同步待处理”，不弹出流程外的询问。
- 前台启动、回前台或联网后尝试同步，失败排队并提供手动重试。用户可在同步页明确选择保留手机修改、采用服务器版本或逐字段合并。容量不足时明确报错，不丢弃尚未同步资料。
- 移入回收站的离线曲目立即从本地节目单隐藏，联网事务提交后双方一致；永久删除和示例清除仍需联网，以避免误判服务端共享引用。
- 验收：断网编辑/创建/节目单排序、App 被杀后队列仍在、附件暂存、重复重试、服务器已有更新、跨端删除、存储不足和迁移失败保护均通过；既有音频缓存可继续播放。

## 7. 阶段 6：扫码点歌台（本地可用版本）

- 主人手动开启一场点歌会话，从曲库选出可公开曲目；默认不公开任何歌曲，不自动公开整库或包含新示例。生成带随机会话令牌和 24 小时有效期的二维码，可提前关闭。
- 访客同一局域网扫码后看公开歌名与才艺类别，搜索并提交点歌；可填昵称，备注最多 200 字。同一访客同一首未处理请求不重复入队，每会话最多 200 个待处理请求，每访客每分钟最多 5 次。
- 访客只获得公开曲目摘要，不获得私人备注、文本谱、来源文件或媒体地址，不播放曲库音频。主人查看队列并接受/拒绝；接受才加入节目单，不插播、不自动发声，不改变当前播放位置。
- 访客路由与管理路由分离。点歌服务关闭时不暴露访客能力；开启前为管理/媒体接口加入设备凭据保护，管理员认证不能只靠“知道局域网地址”。凭据在本机生成，手机通过“我的”一次性配对，不写入 Git、二维码或访客响应。
- 二维码使用 node-qrcode 官方实现，本地生成。会话、公开曲目和点歌记录保存在 SQLite；关闭/过期后新请求拒绝，历史请求可由主人清理。
- 本阶段只交付同网可用版本。它需要 Mac API 可达，不能把二维码当成脱离服务器也可用。公网访问、真实域名、长期服务及离开家后的公开点歌部署留 Human Gate；代码完成不等于公网已经发布。
- 验收：真实手机浏览器扫码、公开范围、重复请求、过期/关闭、主人审批、节目单加入，以及访客无法读写管理接口或访问私人媒体；既有 App 连接与离线播放不退化。

## 8. 公共接口与迁移约定

保留 dance_items 和 repertoire_items 独立主表，不把旧 DanceItem 强行改成包含全部才艺的实体。

| 接口/类型 | 约定 |
| --- | --- |
| ItemRef | {kind:DANCE/GUITAR/VOCAL,id:UUID}，新批量、节目单、谱件统一引用 |
| POST /api/library/bulk | operationId、action、refs、适用字段；update/trash/restore/purge 整批事务，purge 只永久删除回收站记录 |
| GET /api/library/trash | 返回三类已软删除曲目，不混入普通目录 |
| GET/POST/DELETE /api/demo-library | 查询、幂等导入、按登记清除；普通编辑接口不能任意改示例身份 |
| GET/PUT /api/programs/tonight | {revision,items:ItemRef[]}；旧节目单数据一次性迁移且保留原顺序 |
| /api/library/:kind/:id/scores | 查询、上传、排序和解绑谱件；媒体响应只给受控地址，不暴露本机路径 |
| POST /api/sync/operations | 持久操作队列逐项接收，返回 accepted/conflict/failed；同一操作与业务修改原子记账 |
| /api/request-sessions、/api/public/request-sessions/:token | 管理端开关/审批，访客只读公开目录和提交请求 |
| sync manifest | 兼容原 items/playlist/repertoire，增 program、scores、revision、isDemo；旧客户端仍可读取舞蹈内容 |

按阶段新增编号 SQLite 迁移：示例登记与幂等操作记录、混合节目单、谱件、revision/同步、点歌会话；不改已执行迁移。迁移前做一致性备份，在隔离副本验证。每阶段记录旧数据数量、引用和缓存变化；真实数据不得作为破坏性测试对象。
