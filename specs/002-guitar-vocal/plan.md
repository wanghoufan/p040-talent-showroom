# V2 吉他 / 唱歌最小可用版本

2026-10-03 用户明确要求“持续完成到吉他、唱歌”；本窗口单人执行，不恢复编排。V1.5 未完成验收按用户要求暂缓，状态仍 OPEN。V2 使用独立增量基线，不把新才艺塞进 V1.5 固定 DanceItem 语义。

## 范围与验收

1. 曲库上方可切舞蹈 / 吉他 / 唱歌，保持现有舞蹈、四个底部入口及真实数据。
2. 吉他：手动建立曲目，保存歌名/歌手、想学/正在练/会弹、原调/演奏调、Capo0–12、和弦/歌词文本谱、备注。可导入用户音频或带声音视频作为练习示范；保留原始来源。
3. 唱歌：手动建立曲目，保存歌名/歌手、学习状态、原调/演唱调、歌词、备注；导入伴奏或示范音频/视频，标明用途。只用用户内容，不抓取商业歌词/谱。
4. 两类支持搜索、状态筛选、详情查看/编辑、播放/暂停、单曲循环、播放速度、删除记录二次确认。文本谱按换行显示；不自动换调或篡改源音轨。
5. 全部音乐下载包含有音频的吉他/唱歌曲目，离线保存文本/元数据并播放真实本地缓存；无音频的纯文本曲目仍可离线查看，不计入可播放音乐数量。
6. 新增 SQLite repertoire_items，与已有 source_media/performance_clips 关联；不改变dance表、不搬移真实媒体。数据通过现有备份命令统一备份。
7. 新建/编辑/导入依赖本地API；离线查看/播放先实现，离线修改队列另行设计。原始视频播放需要本地API，本轮不批量缓存视频。今晚歌单及现有演出页保留舞蹈语义，才艺详情提供大按钮练习播放。
8. 示例使用独立QA数据库，测试后清除。代码测试、APK构建和固定note11tpro新功能必要测试后交付；旧验收暂不追加。正式签名、长期部署、公开点歌台、访客账号不在本轮。

## 实现顺序

- 全部缓存：真实文件检查、完成/失败数、失败名单、接续重试、停止后保留。
- V2后端：0003增量迁移，分类曲目CRUD，现有ImportJob关联音频，manifest扩展，删除引用保护。
- V2前端：分类入口、曲目列表/文本创建与编辑、详情播放器和音频/视频收录。
- 离线元数据/媒体接入；自动化与固定手机验证；生成APK及更新交接。

新范围授权来源为本轮用户直接指令。上述最小范围采用现有技术栈，未引入云服务、账号或外部识曲凭据。
