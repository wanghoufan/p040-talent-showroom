## 1. P0｜Android A4 PDF 真正落盘、分享、可找到

### 当前缺陷与根因

`src/components/VocalPrintSheet.tsx` 的 `download()` 由 `exportSheetPdf()` 得到字节，然后 `Blob → URL.createObjectURL → <a download>.click()`，即使 Capacitor WebView 未保存文件，也会提示“已生成 N 页 PDF”。这是“生成”与“保存”混淆；不得以 Toast 或下载按钮点击作为落盘成功证据。

### 目标用户流程

唱歌 → 打开一首歌 → 「地图」→ 「A4 学习稿」→ 预览 → 「保存 PDF」→ 成功后显示真实文件名、保存位置/可访问路径，并提供「分享/打开」→ 微信/系统分享或电脑传输 → 文件管理器能定位，其他 PDF 应用可重新打开，直到打印。Web 浏览器路径应保留下载行为，但确认成功文案必须符合浏览器实际可知的结果。

### 技术实现要求

1. 在 Capacitor Native 条件下使用适配 Android 11+ 存储限制的文件写入方式；预检已有 `@capacitor/filesystem`，按平台权限与用户可见性选择 `Directory.Documents`、Android SAF/MediaStore 或可信文件分享机制，禁止假设 app 私有目录等于系统文件管理器的「下载」目录。
2. 如需分享插件或 FileProvider，先查项目依赖和 Android 配置并增量添加；不得冒然改其它项目、申请与文件保存无关的存储权限，不把 base64 文件或 Blob URL 当作永久可分享 URI。
3. 安全文件名（中文/韩文歌名、重复歌名与版本号兼容）、MIME `application/pdf`，文件扩展名 `.pdf`；处理重复保存、不足空间、权限拒绝、取消、写入中断和重试；失败不报成功，也不要留下错误的临时文件。
4. 生成字节只一次，避免大文件重复常驻内存；写完后做 `stat`、大小/摘要等可核验证据，分享给外部应用时采用可读 URI 或系统授权；打开和分享可用性以真机为准。
5. 保持桌面 Chrome 的下载/打印能力，不强制所有端走 Android 专用路径。对短屏按钮、读取中状态、失败重试及返回关闭做 UX 回归。
