## 2. P0｜翻译规则与完整导入链

**唯一产品规则**：中文原唱只显示一行中文，无中文→中文的译文、无「双语」开关、不得发起翻译。韩文/英文原唱：原文在上、对应中文在下，默认可见；可隐藏/纠错。语言未确定或中外文混杂时按歌曲元数据+逐行检测分流，需人工确认时显式提示，不随意猜歌名。原双语 LRC 中已有的中文译文要**与外语行配对**，不额外渲染成下一句原文。

**翻译时机**：开发者在电脑导入所选歌曲及 LRC → 解析时间轴与歌词 → 确认歌曲主要语言 → 对原文/译文拆行和配对 → 中文歌跳过翻译 → 外语歌先复用 LRC 中译文、已有人工译文和缓存 → 仅补译缺失外语句 → 保存按歌词行 ID 关联的中文译文 → 手机端直接使用。对旧数据执行非破坏性展示修复与隔离副本数据审计；绝不能通过清空译文来掩盖问题。

**代码重点**：服务端 `server/vocal-translation/service.mjs` 的 `translateSong` 要显式对 `zh` 返回 `NOTHING_TO_DO`（或同义明确状态），不得进翻译通道；`src/lib/vocal/translation.ts` 的 `summarizeTranslations` 对中文不能累计「缺译文」；`VocalPracticePlayer.tsx`、演出和详情的渲染层均禁止在中文原文下显示同文译文。检查元数据错误、旧 LRC 双语夹行、未标语言与同文译文，制作署名/段落标记不当歌词。人工译文优先且不可被自动覆盖。不得重译已经准确的 1182 行。

**云端边界**：当前 CodeBuddy/DeepSeek 是云端模型而非 Mac mini 本地推理。新调用只在已有授权范围内触发，向用户准确说明；不能用“本地 AI”掩盖云端发送。新模型/费用/Key 是独立决策，未经批准不改变。

**验收 AC-TR-01～06**：至少各用一首真实中文、韩文、英文歌曲；中文页面、PDF、演出均无重复中文、无翻译请求；外语逐行对应、时轴与序号不漂移；老双语 LRC 不重复；缺译文只补缺；人工修正重开仍保留；人工标记和制作信息不被误译。

## 4. P0｜2句/4句/自定义/整段循环：同键开关与范围高亮

**现有根因**：`startLineLoop(count,key)` 无同键二次点击退出逻辑，现有样式只处理 `.vocal-line--active`，没有范围背景。

**状态机**：空闲→点2句，建立当前句向前 N 句（沿用原有规则）的实际循环范围；同一键再点→**清除循环，不 seek、不暂停、不重新开播，保持当前播放位置继续向后**。4句、自定义与本段循环同理；从 2 切 4 或切自定义应切换并重新定位正确范围，旧循环立即失效。自定义打开句数选择后选择即开启；当前选中自定义按钮再次点击直接关闭，修改句数明确重建。暂停时按键只设置/解除，不自动播放。整首循环应与逐句/整段模式冲突明确，不叠加互相抢进度；用户手动跳句/合练仍遵循既有优先级，并写清可理解提示。

**可视状态**：循环中的全部 N 句使用**浅色背景+可辨边框/左侧细条**，当前正在唱的那句有独立更强高亮；循环按钮使用按下态（`aria-pressed=true`），并有短状态文字如 `循环第 07–08 句`。关闭、换歌、退出、切模式时背景和状态立即同步消失或更新。浅色墨水屏优先，深色模式和色弱/黑白屏不能只靠颜色表达；范围应由 `loop.startIndex/endIndex` 得出，不能凭索引猜或只染当前句。

**验收 AC-LOOP-01～08**：点2→按下/两句上色/回跳→再点2取消/继续；点4→再点4取消；自定义选6→再次点取消；2↔4↔自定义切换只保留一档；本段循环同键可取消；暂停操作不开始播放；终点附近取消无意外跳回；无可靠 LRC 时禁用并说明原因。自动化+真机真实音频组合验证。

## 5. P0｜Rap 选择、波形拖动、真正跳过

**现状**：`VocalStructureStudio.tsx` 已有 SVG pointer 手势与 `setPointerCapture`，但用户在手机上反馈 Rap 无法拖动。不可把“代码有 onPointerMove”当通过。

**修复**：用当前指定真机与真实 Rap 段复现，记录视频/触控坐标与拖拽前后时间；查手柄命中半径、手指与鼠标 pointer 行为、滚动/抽屉冲突、边界钳制、SVG 缩放和 pointercancel。增大手柄触控热区至移动端容易点中，视觉手柄不必粗大；增加可见的 `±0.1s/±0.5s` 微调按钮、选段和「在播放位置设分界」，拖失败也能修订。选择类型 Rap → 试听 → 明确确认可跳过 → 保存后再次打开依然存在。只有已确认 Rap 区间进入跳过逻辑；开启跳 Rap、从确认 Rap 内播放，能够真实 seek 到 Rap 结束后。逐句/整段循环优先于跳 Rap，不能被抢跳。用户修订结果不得由机器覆盖。

**验收 AC-RAP-01～06**：真实触摸可选、可拖、可微调、可撤销；保存重开不丢；已确认 Rap 自动跳过、未确认不跳；短屏抽屉可滚到保存按钮；原曲与已有伴奏轨时间偏移正确；离线缓存不影响本地逻辑。

## 6. P0｜A4 分段学习打印

在单首歌的「地图」或其二级操作中提供 **「生成 A4 学习稿」**。产物优先 PDF，可先预览，再下载/分享/打印，用户可用电脑打印。使用现有本地歌词和当前结构作为唯一数据源，不自行上网抓歌词；结构只需机器参考，不强制用户逐段确认。打印标题应标明 `机器参考 / 人工已修订`，避免把算法当官方结论。

**版式**：A4 纵向，建议 12–15mm 页边距；标题、歌手、版本、结构修订 ID、页码；每段按 A1/B1/C1 标题 + 类型 + 起止时间；每行左侧 `mm:ss`、中间原文（外语歌下一行中文）、右侧序号。显示 Rap、Pre-Chorus、Bridge、重复关系和待确认标签；长歌自动分页、段标题不孤立到上一页页尾，留适度手写备注/分段修改空白，避免文字裁切。中文原唱不重复打印中文译文。字号以普通 A4 阅读舒适为主，不能硬挤到一页。打印稿是快照，不会因为导出而保存或改动正式地图。PDF 中文/韩文字体与分页要真实渲染检测，不输出字体原文件。

**验收 AC-PRINT-01～06**：中文、韩文、英文各生成一份；不同长度自动分页；时标/序号/结构标签准确，字符不乱码；黑白打印仍可辨；下载的 PDF 能打开、打印预览无裁切；数据源只读，导出不改地图。

## 7. P0｜纸质人工标注 → AI 修订建议 → 用户确认回写

工作流：打印第 6 节 A4 → 用户手写修改段落界线、类型、重复关系、Rap → 拍照/扫描上传单曲修订入口（电脑文件导入为首选，手机图片导入可选） → 已授权的视觉 AI 从图片**提取更改**，而非凭图片重写歌词 → 生成结构化修订建议（JSON schema、相对旧版的 diff、每项置信度和不能识别的标记） → 用户看到逐项变更、试听/核对 → 点击「确认应用」 → 写入对应歌曲人工结构，保留完整旧版快照、回滚/撤销能力。

**强一致要求**：导出纸上包含不涉隐私的歌曲 ID、歌曲/歌手、结构修订号、可选短校验码；回传先核对 songId、音频版本/时长/必要的哈希及 revision，版本已变化时禁止静默覆盖，进入冲突审查。AI 不得根据照片猜不存在的秒数；手写分界只有歌词行编号时按该行**真实 LRC 时间**对齐，没时间的字段保持待确认。建议与正式地图分开保存，必须用户显式确认；`source=manual` 只用于人工应用的最终结果，AI 提议保持 proposal provenance。禁止云端模型擅自获取未经许可的歌曲原文/个人拍照，上传前明确数据发送对象与是否保留，遵循已有 Key/网关策略；结果文件本项目内留证，不保存不必要隐私素材。

**预检与降级**：检查现有模型是否真的支持图片输入/手写中文识别/结构化 JSON，且已授权；不要把纯文本 DeepSeek 路由伪装成视觉模型。若目前缺少视觉模型/授权，交付**完整的 PDF、JSON 草稿导出/导入、差异预览和手动确认**，AI 图像识别单列 BLOCKED，集中向用户索取必需授权，不假装全流程 PASS。

**验收 AC-PAPER-01～08**：使用一张实际手写 A4 扫描件、无修改稿、错误歌曲稿、模糊稿与旧版本稿；准确提取新增 Rap 和边界变化；错误匹配拒绝；差异可视、确认前不写正式结构、确认后可回滚；无图片/模型时不写假建议；禁止 AI 覆盖人工数据。

## 10. 实施顺序、证据与完成标准
