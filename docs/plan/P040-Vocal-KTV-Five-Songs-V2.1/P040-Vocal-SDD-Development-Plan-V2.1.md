## 2. 目标与产品减法

**唯一用户任务：快速掌握一首歌的不同部分，并能在今晚节目单中安排、缓存，最后以默认伴奏的 KTV 式演出模式现场演唱。**

1. 用户已有或自行准备 MP3 + 对应 LRC，可以从手机导入或者由 Mac mini 通过局域网提供音频，缓存之后离线练。**同一首唱歌曲目允许分别关联原唱 MP3 与伴奏 MP3**；缺一仍能存，但绝不能把一个 MP3 假装成两条音轨。
2. 曲库搜索下方**直接显示**学习状态、语言两组常用标签，可一键筛选，无隐藏筛选入口。
3. 详情页首先显示歌曲结构：前奏、主歌 A1/A2、预副歌、B1/B2 副歌、Rap、尾奏。标出「首次学习」「同词重复」「旋律相似但新歌词」和「可跳过」。避免将重复旋律但不同歌词错误视为无需学。
4. 可播放、暂停、重播、单曲循环；跳进/跳退默认分别 5 秒与 10 秒，设置可选 5/10/15/30 秒。变速沿用既有能力。
5. 任意一句 LRC 逐句点击跳转；「回退 N 句」以当前句为终点，包含当前句，循环从第 max(1, 当前句序号 − N + 1) 句到该句结束，默认 2/4 句，也有自定义 N=3/5 等档位。
6. 「跳过 Rap」开启后**全曲播放时**到达 Rap 的区间自动跳至其后位置，无需重编码。逐句指定练习 Rap 时应尊重显式选择，暂时不自动跳过指定句区间。
7. 「合练一遍」从 0 开始、自动开启跳过 Rap、关闭全曲循环、结束停止。多段 Rap 必须全部跳过。
8. 曲目分析结果与手动校准结果需保存；重启后不应重新计算或丢失结构；音频素材与分析元数据分离。
9. **KTV 双音轨演出**：唱歌加入原有今晚节目单（允许与舞蹈、吉他混排），演出前一键准备离线；演出模式默认选择伴奏，现场可切换「伴奏 / 原唱」。切换必须保持当前位置、播放/暂停状态与歌词同步，不从头开始；演出曲目切换后依旧手动播放，不自动出声。练唱详情优先原唱，亦可切到伴奏。

**不做：** 社交、打分排行、K 歌录音/变声、麦克风混音与 AI 纠音、音高自动评测、歌词实时翻译、在线播放商用版权曲库、账号登录、平台视频下载、云数据库新建、与吉他/舞蹈模块结构性重构、首版自动从单一 MP3 分离人声（需要时后续单独评估）。

## 4. 交互与页面契约

- 唱歌列表保留 **P040 双列封面卡片**和卡内播放快捷键，不改成桌面单列歌单。每卡只放歌名、歌手简写、学习状态、语言与播放。**不展示 Rap 秒数或占比**；Rap 仅在歌曲结构中标注、在播放器中提供跳过开关。
- 初始学习状态不改用户原始值。
- 搜索歌名/歌手；卡片展示演示标识、语言、学习状态和封面。状态在详情可变更；保留原有批量管理入口。
- 手机端曲库 → 详情独立页面，但 **底部四 Tab 持续可见**；主内容可纵向滚动。原型锁定约 390–430 CSS px 手机宽度，即使在桌面打开也显示一台手机宽度的 APP，而非横向扩张；真实 Android 状态栏由系统提供，HTML 里模拟状态栏只用于观感，不可复制成生产硬编码。深浅色两套主题、首次浅色；全局外观入口沿用「我的」，局部操作设置为播放器内部弹层。

### 4.2 详情 / 练唱
- 首屏先展示标题与**结构地图**，每段显示开始时间、段落名称、重复依据/是否可略过，点击跳至相应段。歌词紧邻展示，点击一句可定位。
- 段落语义：`INTRO`/`VERSE`/`PRECHORUS`/`CHORUS`/`BRIDGE`/`RAP`/`OUTRO`。主歌/副歌命名 A1、B1、A2、B2 仅做清晰记忆；预副歌可称 P1；桥段 C1。
- 如 B2 旋律与 B1 相同但歌词不相同，标注「旋律重复、歌词不同」，**不能**标「跳过学习」。必须有 Rap 类型 + 起止时间才能跳过。
- **手机播放器底部固定在四 Tab 上方**（独立 dock）：第一行紧凑进度条和时间；第二行五个等位按钮「重播 / −5s / 播放·暂停 / +10s / 单曲循环」；第三行「跳过 Rap / 合练一遍 / ⚙练习设置 / 倍速」，保留足够触控面积。不得再以 PC 宽屏的大按钮堆排成两行或横向溢出。
- **「2句循环 / 4句循环 / 自定义 N 句」位于歌词区标题下方，始终在单行内**，点歌词选起点、可随时退出。循环边界取 LRC 时间戳及下一句起始时间；最后一句取段落终点/音乐总时长；若无可靠时间戳禁用逐句循环并告知用户补充校准。

### 4.3 原有今晚节目单 + 演出模式（本次实际新增的 UI/数据契约）

**原四个底部 Tab 不变**，不能额外创建“唱歌 KTV”Tab，也不能把原节目单或演出模式用原型占位版取代。现有 `TonightPlaylistPage.tsx`、`PerformancePage.tsx`、`src/lib/program.ts`、`src/lib/sync.ts` 必须由主开发者按现有数据及路由做兼容改造。

- **唱歌曲目详情**：提供原唱、伴奏选择，练唱模式有原唱时优先原唱；新唱歌曲目允许两份 MP3 分别上传或补录，不能依靠旧版单一 `audioRole` 字段进行假切换。歌曲详情提供「加入节目单」，添加的是曲目引用，而不是单独的伴奏文件。
- **今晚节目单**：继续支持舞蹈/吉他/唱歌混排、去重、拖动排序和缓存准备。准备离线演出时，唱歌默认需要伴奏、同步歌词和结构信息；如有原唱还应把原唱作为可切换资源缓存。缓存完成必须实际校验所有要求资源的文件存在且可解码，不能只验证数据库索引。部分缺失时列出具体歌曲和缺失的原唱/伴奏文件。纯文本歌曲维持旧逻辑。
- **演出模式页面（手机）**：现有顶部标题「演出模式」→ 当前歌曲名称/序号 → 醒目的「♫ 伴奏」「♬ 原唱」双按钮（默认伴奏）→ 时间轴 → 上一首、播放/暂停、重播、下一首 → 大字号同步歌词 → 当晚节目单简表；原有四 Tab 固定底部，页面单列、无 PC 分栏。**进入演出及切换到下一首歌均重置为伴奏，不自动播放**。如伴奏缺失，应标「未提供伴奏」而不是把原唱作为伴奏自动播出；用户可以手动选择原唱。
- **音轨切换**：同一首歌、同一编排版本的 `original` 和 `accompaniment` 分别引用独立媒体 ID；切换前记录 `currentTime`、`paused` 和必要音量/倍速，加载目标源后跳转到相同时间再恢复原来播放状态；歌词、进度和结构时间轴不重新开始。音轨可能有音频编码、静音前奏或结构差异，导入时必须检验时长/对齐，如需调整保留独立 `offsetMs`；不保证跨来源的完全无缝零延迟。失败时回退旧轨或清楚显示错误，不自动乱播。
- **演出与练习隔离**：演出不自动继承练唱的跳过 Rap、N 句循环、整曲循环、变速或一次性去 Rap 合练设置；演出默认完整伴奏、1.0×、单次播放。即使未来开放演出跳 Rap，也必须是演出内单独的、明确的开关，不能由训练页隐式继承。
- **音轨缺失**：单份原唱、单份伴奏、只有歌词、文件损坏、断网、缓存丢失分别可见；不可凭一个 MP3 的元数据向用户保证已经拥有「伴奏」或「原唱」。要获得真正干净伴奏，用户需另行提供伴奏文件；自动人声分离不属于本次基本要求。
- **素材示例边界**：五首 demo 是伴奏 MP3 与额外合成导唱旋律 MP3，供切轨逻辑测试；没有任何真人演唱。原型里的节目单/离线准备是交互模拟，**正式 App 的真实缓存与真机播放需独立验收**。

### 4.4 文件与分析状态
- Android 系统多文件选择，Mac mini 同网可批量导入 MP3/LRC；同名匹配大小写及文件名规范化，冲突/不匹配先列问题，不擅自覆盖。
- 两种来源：本地已缓存音频/局域网服务器音频；优先复用现有 `queueFile`、`playbackSource`、`offline-manifest`、SQLite `repertoire` 数据模型，不新建重复媒体存储系统。
- 真实自动分析**优先参考 LRC、音乐分段特征、重复歌词**，必要时接入经测试可用的音频/音乐结构检测方法；不得未经验证就承诺准确率。模型无法判别则给出待校准状态，保留手工快速标注作为必备回退。不得把人工 demo 标签当自动识别结果。
- 结构分析应可异步运行并缓存，不能阻塞简单播放；没有模型 API Key 的情况下，手工标注 + 完整播放器仍可用。用户导入歌曲之后能进入详情，不强制 AI 成功。

## 4.5 UI 布局冻结（本轮用户截图确认的正确方向）

1. **基础壳层不变**：Android 系统栏（由系统提供）→ 曲库内容 → 固定四 Tab。曲库顶部三个才艺分类按钮与「批量管理」「+」同排；搜索单行；状态单行；语言单行；双列曲卡。与用户提供的 12T Pro 实机截图一致。
2. **详情向下钻取但不另起应用**：左上角返回；右侧学习状态；结构区置顶，彩色时间带 + 按时间顺序的两列紧凑段落，标记 A1/B1/R1/重复等；紧接同步歌词和按句循环。内容区只纵向滚动，底部练习 dock 和四 Tab 不随内容滚动。
3. **样式与密度**：以 390 CSS px 视口设计，兼容 360–430 px；顶栏高约 48、搜索 44、每组标签约 36、底部 Tab 约 70、播放 dock 约 130–145 CSS px。控件宽度由容器自适应，严禁绝对像素定位造成遮挡；宽屏展示 HTML 时固定手机宽度，不扩成网页桌面布局。
4. **设置关系**：底部「我的」仍保存 P040 原有主题、Mac mini 配置、离线音乐和同步等；详情 ⚙ 仅修改当前练习习惯（前后跳秒数、自定义按句数与必要局部播放行为），不可复制一个新的全局设置首页。主题默认浅色、允许切换深色，跨会话保存。
5. **Rap 的定位**：不提供 Rap 分类筛选、不显示占比或比例统计；在结构段落以「Rap R1」说明位置，在播放器保留“跳过 Rap”开关。用户只关心能否跳过，不能让 Rap 标签占据曲库首屏。
6. **导航范围边界**：V2.1 HTML 对唱歌、今晚节目单和演出模式提供真实可点的交互演示；「我的」、舞蹈、吉他为保持现有入口而做的占位展示。正式版仍须**复用并增量改造 P040 原页面**，不能以原型整体覆盖现有业务逻辑。

## 5. 建议数据结构与兼容策略

保留既有 `TalentItem`、`scoreText`、`audioRole`、`audio` 和旧接口，在兼容迁移中增加可选关联对象，而不是替换旧表。建议对象：

```ts
type VocalSectionType = 'intro'|'verse'|'pre'|'chorus'|'bridge'|'rap'|'outro'|'unknown';
type VocalSection = {
 id:string; type:VocalSectionType; label:string;
 startMs:number; endMs:number;
 repeatOf?:string; repetition?:'exact-lyrics'|'same-melody-new-lyrics'|'unverified';
 source:'manual'|'algorithm';
};
type TimedLyric = { id:string; startMs:number; text:string; sectionId?:string; endMs?:number };
type VocalPracticeSettings = {
 skipRap:boolean; wholeTrackLoop:boolean;
 backwardSeconds:5|10|15|30; forwardSeconds:5|10|15|30;
 customRepeatLines:number; playbackRate:number;
};
// 唱歌新增可选双音轨，不替换或篡改旧 TalentItem.audio/audioRole。
// 旧单音频按旧 audioRole 精确映射到其中一轨，另一轨保持 null。
type VocalTracks = {
 original?: {media:MediaFile; offsetMs?:number};
 accompaniment?: {media:MediaFile; offsetMs?:number};
};
type PerformanceSource = 'accompaniment' | 'original';
```

- 分段时间为半开区间 `[startMs, endMs)`，Rap 合并并去重叠，跳过后继续播放，防止 Seek loop。若两个 Rap 相邻应合并区间；若数据越界、开始≥结束拒绝保存。
- 逐句重复以当前句为终点，取之前 N-1 句，优先使用 LRC 有效时间；无可靠句尾就用下一有效句起点，允许可选 0.1–0.3 秒缓冲，但不得过多截词。手工校准覆盖自动分析结果，重新分析时绝不可静默覆盖手工修改。
- 本地优先保存音频 UUID/manifest，MP3 文件与 LRC 元数据分开；导入队列断网持久化、重复文件识别和冲突处理遵守 P040 现有约束。
- 分析来源、模型版本、时间戳、编辑记录可存在内部数据结构，不展示在普通用户 UI 首页。
- 正式迁移应为 `VOCAL` 增加原唱/伴奏两个可选媒体关联，`GUITAR` 和 `DANCE` 的现有媒体结构保持兼容；节目单仍存 `{kind,id}`，不为音轨创建重复曲目；原唱与伴奏的媒体缓存条目按 source/version/hash 独立校验。

## 6. 实施计划（唯一主开发者连续完成）

**阶段 0 — 安全基线和最小验证**：读当前工作区 AGENTS、HANDOFF、旧 SPEC、全部相关代码与本地 Git diff；区分已有用户修改、曾冻结区域；备份现有 SQLite+媒体索引和当前 Git 状态，优先使用 DB 副本测试；保持 release 与 `.dev` Android 包名及原有数据隔离。

**阶段 1 — 数据与导入**：新增 LRC 解析、MP3/LRC 多文件配对、导入结果提示、可选歌词存储和导入队列恢复；唱歌媒体增加原唱/伴奏双可选关联和可辨识的文件用途，旧 `audioRole` 不删除，历史单音轨只映射到对应角色。测试中文、英文、韩文 UTF-8、带 BOM、无歌词、重复文件、断网与再次进入。

**阶段 2 — 分析结构**：节段对象/持久化、结构地图、重复标记、Rap 区间操作和手工校准。将样例人工标注与实际分析模块严格分开；批量任务可本机 Mac mini 队列运行，不阻塞播放器。先实现可用而不虚构的分析回退，再选择经验证的自动识别技术方案。

**阶段 3 — 播放器**：复用 HTML audio / 现有 Android 来源适配，增加进退 5/10/15/30 秒、Rap 自动跳段、重播、单曲循环、独立一次性合练，准确处理用户拖动进度条与多 Rap；同一曲目原唱/伴奏在当前时间点切换，保留播放状态，处理切轨超时和不匹配时长。

**阶段 4 — 按句训练**：LRC 高亮、点击跳句、固定 N 句循环、自定义 N、暂停/恢复、重进详情记住位置和常用设置；当前区间与 Rap 跳段的优先级明确。

**阶段 6 — 验证与交付**：使用本包 5 组伴奏 MP3 + 合成导唱 MP3 + LRC + 用户自选真实歌曲做逐项验收，跑 `typecheck`、`test`、`lint`、`build`、相关 API 集成测试；真机安装需用户允许且在锁定指定设备上执行。必要时补做断网冷启动测试。变更说明/README/交接更新，最后呈现完成情况与实际证据。不得因阶段或普通测试等待新的用户“继续”。

## 7. 精确验收用例

1. 唱歌曲库默认仅有两行筛选「状态」「语言」，分别一行排完且无 Rap 筛选；切换「韩文」仅出现韩文样例，组合「英文 + 已学会」按状态生效，深浅色均清晰可读。
2. 5 首样例均可播放 MP3，中文/英文/韩文 LRC 正确渲染；曲目切换停止上一首，不出现串播；顶部三才艺分类与底部四 Tab 永远存在，唱歌详情的播放器 dock 在底部 Tab 之上。
3. `harbor/window` Rap 0s，开启跳 Rap 时播放时间不应被跳错；副歌 B2 可指出与 B1 是内容重复。
4. `city` 播放 28s→38s 前后时跳过 29–37s，下一主歌继续；关闭跳 Rap 后能播放 29–37s。
5. `pulse` 进入 4s、34s 两次 Rap 区间时都跳到分别 22s、54s（允许音频播放调度误差）；合练只播放非 Rap 段，播放到尾停止。
6. `orbit` 韩文字体无乱码，27–40s 副歌、40–54s Rap、54–67s 重复副歌顺序正确。
7. 点击第 8 句再「回退 4 句」，循环第 5–8 句，不按时间均分；Rap 显式逐句练习可以不受跳 Rap 开关影响。
8. `5/10/15/30` 秒档位前进/后退边界在 0s/结尾有夹取；全曲循环与一次合练不会冲突；暂停/播放不自动丢练习区间。
9. 导入 MP3 + LRC 匹配成功、缺歌词也能播放、无可用时间戳显示“需要校准”、结构暂不可确定时不宣称 AI 已识别。
10. 进入演出默认「伴奏」选中，若无伴奏必须明确提示；切回原唱后继续从同一时间点播放，切换前暂停则切换后仍暂停。下一首恢复伴奏但不自动出声；断网时两条已缓存音轨和同步歌词均可用，缺某条时不假装成功。
11. 今晚节目单混排唱歌、舞蹈与吉他，每首唱歌只占一个节目条目，缓存准备会校验两种音轨及歌词结构；已缓存文件不重复下载，坏文件被识别并可重试。
12. Android 真机升级不清除原 31 首曲目、舞蹈/吉他/节目单/缓存；测试 DB 副本与真实数据分离；用户原有未提交修改保持完整。
