# QA_RESULT｜《绿光》歌词时间轴修复（2026-11-06）

## 现象
Note 12T Pro 上唱《绿光》时，高亮歌词比实际演唱晚一句（用户描述「差了一句话」）。

## 根因
不是缺句，**是 LRC 时间轴本身错位**。

- 曲目 `a3872d36-462f-57ea-82ce-0e32235b967e`（绿光 / 阿成哥），歌词 56 行**文字完整**（网易云 LRC 原样，逐行核对无缺行）。
- 音频与网易云该曲官方时长 188030ms 完全一致（本地 188031ms），**不是歌源/版本不同**；问题在导入的 LRC 时间锚点。
- `startMs` 来自该 LRC，实测比真实起唱点晚 0.4–10.7 秒且无规律（如第 8 行 Green light 旧 24.07s、实际 19.48s；第 24 行 So long goodbye 旧 75.06s、实际 64.40s；第 55 行 旧 177.47s、实际 170.4s）。
- 结果：每句唱完旧时间点才到，高亮永远落在「下一句/上一句」——听感就是差一句。

## 处理
用本地 whisper.cpp（base，token 级时间戳）+ OpenCC 繁简归一 + 字符级 SequenceMatcher 对齐 56 行，得到逐行新起点；
ASR 在多段音乐处失真（啦啦啦 / Na / 英文段）时用隔离窗口复核结果人工锚定。

| 项 | 值 |
|---|---|
| 改动范围 | 仅 `lyrics_json.startMs`；`text`/`id` 未变（脚本断言校验） |
| revision | 7 → 8 |
| 备份 | `var/backups/qa-real-20261030-pre-lyric-timing-20261106-204938.db`（回读 revision=7、原时间 24.075s 完好） |
| 单调性 | 56 行 `startMs` 严格递增，最大行距 10.48s（So long goodbye → Green light，含间奏） |

关键锚点（新时间 / 秒）：
- 0 期待着一个幸运和一个冲击 → 0.00
- 8 Green light I'm searching for you → 19.48
- 24 So long goodbye → 64.40
- 37 啦啦啦啦啦啦 → 114.60
- 48–52 Na ×5 → 149.3 / 152.5 / 155.7 / 158.9 / 162.1
- 55 你就是唯一 → 170.40（音频 188.03s，后有间奏与片尾水印，未再补句）

## 他曲普查（8 首唱歌曲目）
方法：**全曲权威 ASR**（base 模型 + 该曲语言 + 词级时间戳；韩语重曲改用 small）+ 仅取「全文唯一且长度≥6」的歌词行，在 ±5s 内按「离歌词时间最近」原则匹配，阈值 sim≥0.85。

> 已废弃的 qc2（small 全曲批跑）实测会把前半段逐渐拖后最多 8s（与隔离窗口矛盾），不作为判据；早期按「最高相似度」匹配会被全曲 ASR 的同句幻听带到远处（修好的绿光仍报 -4s），已改为最近匹配。

## 未覆盖
- 无法在真机上「用耳朵复听」（自动化验收只证明渲染的时间轴与音频 ASR 一致，听感仍需用户最终确认）。
